# B2 officielle — feuille d'exécution manuelle

**Phase :** 8 — étape 4  
**Scénario :** client/médecin synthétique → node1 → diffusion P2P → node2/node3  
**Date de départ :** 14 septembre 2026  
**Statut :** première passe officielle exécutée jusqu'à 2 tx/s ; la répétition confirmatoire r05 rep02 reproduit 119/120 et la zone de saturation observée est retenue à 2 tx/s. Voir `phase8-b2-official-results-2026-09-14.md`.

## Règles fixes

- Aucun appel IPFS dans cette campagne.
- Aucune règle `tc-netem`.
- Le générateur contacte uniquement node1.
- Payload contrôlé, synthétique et non médical : `--payload-size 0`.
- Ne jamais supprimer `keys/` ou `config/`.
- Pour chaque répétition indépendante, supprimer uniquement les fichiers
  `data/nodeN/blocks/*.json` après arrêt propre des trois nœuds.
- Ne pas utiliser `make clean-data` ni `pkill -f`.
- Les commandes ci-dessous sont à exécuter manuellement ; ce document n'est
  pas un script d'orchestration.

## Matrice officielle proposée

Une répétition comporte 60 secondes de mesure et un drain documenté. Les taux
sont exécutés séparément sur une chaîne fraîche :

| Run | Taux offert | Transactions préconstruites par 60 s |
|---|---:|---:|
| r01 | 0,1 tx/s | 6 |
| r02 | 0,2 tx/s | 12 |
| r03 | 0,5 tx/s | 30 |
| r04 | 1 tx/s | 60 |
| r05 | 2 tx/s | 120 |
| r06 | 5 tx/s | 300 |

La quantité effectivement commise, les échecs et le backlog sont toujours
ceux observés dans les journaux et les trois répertoires de blocs ; les nombres
du tableau ne sont pas des résultats de TPS.

Pour une campagne complète : 5 répétitions indépendantes par taux. Il est
recommandé de commencer par `r01` puis de vérifier le résumé avant de
continuer aux taux supérieurs.

## Démarrage d'une répétition

Après arrêt propre d'un éventuel run précédent, réinitialiser uniquement les
blocs sur les trois VMs :

```bash
ssh <user>@192.168.168.101 'rm -f ~/blockchain-experiment-distributed/data/node1/blocks/*.json'
ssh <user>@192.168.168.102 'rm -f ~/blockchain-experiment-distributed/data/node2/blocks/*.json'
ssh <user>@192.168.168.103 'rm -f ~/blockchain-experiment-distributed/data/node3/blocks/*.json'
```

Démarrer ensuite les trois nœuds dans trois terminaux distincts, en conservant
les journaux :

```bash
# node1
cd ~/blockchain-experiment-distributed
source .venv/bin/activate
export OQS_INSTALL_PATH=$HOME/_oqs
export LD_LIBRARY_PATH=$OQS_INSTALL_PATH/lib:${LD_LIBRARY_PATH:-}
make node1 2>&1 | tee /tmp/b2-official-r01-node1.log
```

Utiliser la même commande avec `make node2` et `make node3` sur les VMs
correspondantes, en nommant les journaux `node2` et `node3`.

Vérifier avant la charge : port `9001` en écoute, pairs connectés, genesis
identique et hauteur initiale identique.

## Premier run officiel : r01 à 0,1 tx/s

Sur node1 uniquement :

```bash
cd ~/blockchain-experiment-distributed
source .venv/bin/activate
export OQS_INSTALL_PATH=$HOME/_oqs
export LD_LIBRARY_PATH=$OQS_INSTALL_PATH/lib:${LD_LIBRARY_PATH:-}

PYTHONPATH=. python3 scripts/experiments/benchmark_b2_baseline.py \
  --config config/nodes/node1/node.yaml \
  --rate 0.1 \
  --duration 60 \
  --payload-size 0 \
  --drain-timeout 120 \
  --data-dir "$PWD/data/node1" \
  --run-id b2-official-r01-0p1-20260914 \
  --manifest-output results/raw_data/b2-official-r01-0p1-20260914-node1-manifest.json
```

Le générateur doit être lancé une seule fois : node2 et node3 ne reçoivent pas
de soumissions directes.

référence :

scp <user>@192.168.168.101:~/blockchain-experiment-distributed/data/node1/blocks/*.json /tmp/b2-official-r01-0p1-20260914/node1/blocks/
scp <user>@192.168.168.102:~/blockchain-experiment-distributed/data/node2/blocks/*.json /tmp/b2-official-r01-0p1-20260914/node2/blocks/

Analyser localement :

```bash
cd /home/user/repo
PYTHONPATH=. python3 scripts/experiments/analyze_b2_baseline.py \
  --manifest results/raw_data/b2-official-r01-0p1-20260914-node1-manifest.json \
  --node1-blocks /tmp/b2-official-r01-0p1-20260914/node1/blocks \
  --node2-blocks /tmp/b2-official-r01-0p1-20260914/node2/blocks \
  --node3-blocks /tmp/b2-official-r01-0p1-20260914/node3/blocks \
  --node1-log /tmp/b2-official-r01-0p1-20260914/node1.log \
  --node2-log /tmp/b2-official-r01-0p1-20260914/node2.log \
  --node3-log /tmp/b2-official-r01-0p1-20260914/node3.log \
  --output results/raw_data/b2-official-r01-0p1-20260914-summary.json
```

Le résumé doit comporter explicitement : soumises, acceptées par node1,
acceptées localement par nœud, incluses sur chaque nœud, commises sur les trois
nœuds, réussies/échouées, TPS commis, goodput, latences, backlog, hauteur,
`block_hash` et `state_root` finaux. La convergence temporelle reste
`not_measured` sans synchronisation indépendante des horloges.

## Critère avant le taux suivant

Ne passer à `r02` qu'après vérification de r01 :

- manifeste lisible et sans secret ;
- node1 seul point d'entrée ;
- logs des trois nœuds présents ;
- blocs lisibles sur les trois nœuds ;
- aucun doublon inattendu ;
- même préfixe de chaîne, `block_hash` et `state_root` ;
- les transactions non commises sont conservées dans le backlog et non
  présentées comme réussies.
